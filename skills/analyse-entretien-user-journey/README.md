# analyse-entretien-user-journey

**Le problème :** après un entretien utilisateur, la synthèse se fait de mémoire ou à partir du résumé automatique, qui se trompe. Les post-its qui en sortent n'ont plus de source.

**Ce que fait le skill :** il part du transcript intégral, détermine d'abord le rôle du participant, puis remplit la user journey de ce rôle. Chaque post-it porte sa source : verbatim minuté, observé, déduit, lacune ou note du binôme.

**Ce qu'on obtient :**
- une page HTML à onglets : synthèse, journey, verbatims, qualité de l'entretien ;
- un fichier de post-its à coller dans Miro ou FigJam ;
- le transcript pseudonymisé.

**Exemple (fictif) :**
> « Analyse l'entretien "Atelier Vélo – P3" dans Fireflies et fais-moi la user journey. »

Le skill annonce d'abord : « Rôle retenu : cycliste (« j'ai réservé un créneau mardi », 04:12) », puis produit la fiche. Il signale 3 post-its `[déduit]` et 2 questions orientées à corriger pour l'entretien suivant.

**Prérequis :** un transcript (connecteur Fireflies ou texte collé).
