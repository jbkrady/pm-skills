# business-analysis

**Le problème :** une question anodine (« et si l'utilisateur ne fait pas X ? ») révèle qu'un cas n'a jamais été tranché. On le comble par une supposition, et elle devient un acquis que personne n'a décidé.

**Ce que fait le skill :** trois explorations en parallèle (le code réel, la vérité produit, les produits comparables), puis il sépare ce qui est **déjà décidé** de ce qui ne l'a **jamais été**, cherche les contradictions, et présente les décisions en 2 ou 3 options avec une recommandation. Il ne tranche jamais à votre place.

**Exemple (fictif) :**
> « Et si un cycliste annule moins d'une heure avant son créneau ? On n'a jamais pensé à ce cas. »

Le skill répond : ce que fait le code aujourd'hui (rien : l'acompte n'est jamais remboursé ni retenu), ce que disent les specs (rien non plus), ce que font trois produits de réservation comparables, puis trois options avec leurs conséquences pour l'atelier et pour le cycliste.

**Principe :** un trou dans les specs est une information. On le nomme, on ne le bouche pas.
